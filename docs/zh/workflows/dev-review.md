# 深度双审共识闭环（`/dev-review`）

Review-dev 对核心高危代码执行**架构师 + 快速 P0/P1 审查 + max 终审门禁**。它是[五档开发流](dev-loops.md)之一——深度共识哲学：独立审查者从不同角度攻击 diff，顾问按 Safety-First 原则仲裁分歧。

> 本命令已实现为 [`/dev`](dev.md) 引擎的 `--code-review=2` 预设。

---

## 工作流

```
1. 编码   @<lang>-dev（按领域路由）——阅读原始需求，跨所有涉及层实现；
          完成前按 test-scope.md 层级跑测试
2. 审查A  @architect——"需求可追溯性与契约镜头"：
          规范覆盖度、架构凝聚力、契约完整性
3. 审查B  @code-review-fast——"防御质量与弹性镜头"（仅 P0/P1）：
          边界条件、并发安全、错误恢复、严格类型
4. 终审   @code-review——max 深度终审门禁
5. 共识   双审通过 → 进入终审；分歧 → 修复循环（上限 10 轮）
6. 仲裁   @advisor——Safety-First 原则解决分歧
7. 交付   验证报告 + 终审签署
```

## 双审协议

两位审查者共享相同的证据驱动基线（Execute → Observe → Match），但通过不同镜头运作：

### 审查者A——架构与契约镜头（`@architect`）

- **需求可追溯性**——用户原始提示中的每条需求必须映射到精确代码；未实现 = 发现
- **反偷懒与契约防御**——范围裁剪、伪 mock、空 TODO、仅 happy-path 逻辑；跨模块 DTO 与 API 契约适配
- **裁决**——仅当每条需求都可追溯且无架构缺陷时才 APPROVE

### 审查者B——防御工程与弹性镜头（`@code-review-fast`）

- **防御性代码审计**——null/undefined 安全、错误恢复、资源释放、严格类型（零任意 `any`）
- **极端压力与并发**——竞态条件、线程安全、边界溢出、未处理的异步拒绝
- **裁决**——仅当无具体缺陷时才 APPROVE

## 仲裁

当审查者意见分歧（一方通过一方拒绝，或建议冲突）时：

1. 将冲突点 + 原始需求 + 两份报告派发给 `@advisor`
2. **Safety-First 原则**——在安全性、正确性、数据完整性有疑问时，始终倾向更严格的要求
3. 顾问输出最终合并的**可执行修复清单**

## 选型指南

| 场景 | 选择 |
|---|---|
| 核心高危：分布式事务、全栈跨端、安全敏感 | `/dev-review` |
| 希望审批计划，审查可选 | `/dev-plan` |
| 安全攸关，需要 FMEA | `/dev-prud` |
| 大型自主多阶段目标 | `/dev-ultra` |
| 临时脚本，无需审查 | `/dev-quick` |

## 用法

```bash
# 核心高危功能——双审 + 仲裁
/dev-review 重构资金清结算分布式事务与幂等状态机

# 全栈功能带扩展审查循环
/dev-review 实现扫码登录全流程：会话表、轮询接口、弹窗组件 --max-rounds=10
```

参数：`--max-rounds=N`（最大迭代轮次，默认 10，范围 1–99）。
