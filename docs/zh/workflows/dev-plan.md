# 计划先行开发（`/dev-plan`）

Plan-dev 在**任何代码存在之前**前置执行需求澄清与实现计划编制。它是[五档开发流](dev-loops.md)之一——计划先行哲学：在第一行代码写下之前就看见并审批计划，然后按需执行带审查的实现。

> 本命令已实现为 [`/dev`](dev.md) 引擎的 `--plan` 预设。

---

## 工作流

```
1. 澄清   @advisor 苏格拉底循环——批量提问（FACTUAL/PREFERENCE 标注），
          矛盾检测，最多 3 轮；悬而未决项转为显式假设
2. 计划   @architect——结构化实现计划，含步骤拆解、
          Agent 分配、风险备注
3. 确认   用户门禁——或 auto-advisor full 模式代理确认（FACTUAL、≥ 8）
4. 实现   @<lang>-dev（按领域路由）——按确认后的计划执行；
          完成前按 test-scope.md 层级跑测试
5. 审查   （可选，--review 标志）按分级规则执行证据驱动审计；
          修复循环上限 5 轮
6.   交付   验证报告 + 计划执行摘要
```

## 计划产物

计划是需求与实现之间的契约，包含：

- **步骤拆解**——有序，每个步骤：做什么、涉及哪些文件、依赖关系
- **Agent 分配**——按领域路由（`@node-dev`、`@python-dev`、`@dba` 等）
- **风险备注**——任何可能失败或需要特别关注的步骤
- **假设清单**——澄清阶段未解决问题的显式记录

## 澄清阶段

苏格拉底式澄清使用 `@advisor` 来暴露模糊性、边界情况和隐式约束：

1. **批量提问**——所有问题通过 `question` 工具一次性呈现，标注 FACTUAL（可验证）或 PREFERENCE（用户选择）并附置信度
2. **矛盾检测**——用户回答后，顾问检查矛盾；若发现则仅重新提问矛盾点（最多 3 轮）
3. **Auto-advisor 兼容**——full 模式自动采纳置信度 ≥ 8 的 FACTUAL 问题；lite/off 模式全部呈现给用户
4. **兜底**——3 轮后仍有未解决的模糊性时，继续执行并将所有未解决问题作为显式假设记录在计划头部

## 可选审查

默认情况下，dev-plan 完全跳过审查以获得最大速度。使用 `--review` 时：

- 默认 `@code-review-fast`；敏感路径、L3 和终审使用 `@code-review`
- 最多 5 轮修复循环（可通过 `--max-rounds=N` 配置）
- 与其他流相同的审计协议：需求可追溯性、防御性代码审计、反偷懒检查

## 选型指南

| 场景 | 选择 |
|---|---|
| 希望在编码前审批计划 | `/dev-plan` |
| 临时脚本，无需计划 | `/dev-quick` |
| 核心高危，需要双审 | `/dev-review` |
| 安全攸关，需要 FMEA | `/dev-prud` |
| 大型自主多阶段目标 | `/dev-ultra` |

## 用法

```bash
# 标准计划先行开发
/dev-plan 实现用户个人中心头像上传与裁剪组件

# 带可选单审审计
/dev-plan 添加支付回调处理 --review

# 带扩展审查循环
/dev-plan 重构订单服务 --review --max-rounds=8
```

参数：`--review`（启用单审审计，默认关闭）、`--max-rounds=N`（启用 `--review` 时的审查修复轮次，默认 5，范围 1–99）。
