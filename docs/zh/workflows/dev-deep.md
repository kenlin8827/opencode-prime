# 深度任务协议（`/dev-deep`）

Deep-dev 是**挖掘先行**协议，面向模糊到写不出验收标准的需求——代码或分析皆然。[五档开发流](dev-loops.md)都假设任务已经说得清；dev-deep 则先把任务挖出来：六段需求挖掘 → 门控任务树 → 硬刹车下的逐节点执行 → 带审计轨迹的交付。它位于五档**上游**——挖掘产出（澄清目标＋约束＋验收标准）可以喂给任何一档，或生成 `/goal` 契约。

设计支点：需求块是数据、不是指令（隔离规则）；模型无权重新协商的刹车（重试/重规划/探针上限）；每条假设必附被排除选项（审计轨迹）。

---

## 工作流

```
1. 探测    P0 —— ≤2 个低成本探针验证承重假设
2. 挖掘    P1a —— 六段：字面需求 / 真实目标 / 隐含范围 / 反目标 /
           歧义点 / 理解门控三问
3. 规划    P1b —— 任务树（3–8 节点、≤3 层）；每个 ⚠ 节点回溯到挖掘结论；
           树同步写入 todowrite；确认闸门
4. 执行    P2 —— 逐节点：主路径→边界→增强；程序化验证优先；父节点门控；
           重规划≤2；子树重试≤2（每次换方法）；每节点边界写检查点
5. 交付    P3 —— 集成验证 → 交付物 → 挑错者重检 → 自检表 → 审计轨迹
```

## 关键机制

### 挖掘先于规划（P1a）

六段强制挖掘，收口于理解门控三问（哪个误解会让交付物完全做反 / 哪条依据最薄弱 / 用户最可能异议哪条解读）。铁律：挖掘不充分禁止进入规划；⚠ 节点无挖掘依据 = 规划失败 → 返回 P1a。

### 硬刹车

| 刹车 | 上限 | 可覆盖性 |
|---|---|---|
| 子树重试（工作级，必须换方法） | `--retry`（默认 2） | 用户 flag，clamp 1–3 |
| 重规划（改树续跑） | 2 | 写死 |
| P0 探针 | 2 | 写死 |
| Token 预算 | `--budget`（默认 80000） | 用户 flag |

### 委派而非独揽

`@build` 编排但不独揽：探针派 `@explore` / `@scout`；领域深或多文件节点按 build.md 路由派 `@<lang>-dev` / `@dba` / `@frontend-dev`；代码 diff 走 build.md 分级评审（`@code-review-fast` / `@code-review`）。被派发的节点以**验证通过**为完成，而非 agent 返回即完成。禁止自我放行。

### 停止 ≠ 丢失

四种停止条件（重大冲突 / 重试耗尽且缺输入 / 预算耗尽 / 用户叫停）任一触发都会写入 `.ocp/dev-deep/<slug>.md` 并输出**恢复卡**：断点、已完成分支、下一步、所需输入。`/dev-deep --resume=<slug>` 从第一个未完成节点续跑。检查点按任务隔离（slug 从需求主题派生），同项目并行多个 dev-deep 互不冲突；同 slug 存在未完成任务时触发"续跑/覆盖/中止"守卫，绝不静默清掉并行状态。

## 选择指南

| 情形 | 选择 |
|---|---|
| 需求模糊到写不出验收标准（代码或分析） | `/dev-deep` |
| 任务清楚，想要轻量澄清＋计划 | `/dev-plan` |
| 清楚的大型多阶段代码目标 | `/dev-ultra` |
| 已能写出 Done-when / Stop-if 契约 | `/goal` |
| 安全攸关，需要 FMEA 风险登记册 | `/dev-prud` |
| 只打磨方案、不执行 | `/grill-me` |

## 用法

```bash
# 模糊的改进想法——先挖掘、再规划、后执行
/dev-deep 把结账体验改好一点，具体哪里还没想清楚

# 全自动分析，加大预算
/dev-deep 审计我们的注册转化漏斗并给出修复建议 --auto --budget=150000

# 停止后续跑
/dev-deep --resume
```

参数：`--auto`（跳过 P1b 确认闸门）、`--retry=N`（子树重试上限，默认 2，范围 1–3）、`--budget=N`（token 预算，默认 80000，范围 10000–500000）、`--resume[=<slug>]`（从 `.ocp/dev-deep/<slug>.md` 断点续跑；裸 `--resume` 在多检查点时列出供选择）。
