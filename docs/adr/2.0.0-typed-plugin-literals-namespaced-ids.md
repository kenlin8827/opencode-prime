# 2.0.0 · Typed plugin literals, namespaced plugin ids, zero runtime imports

> Amends ADR-2.0.0#01 (plugin API point 1: `Plugin.define({ id, setup })`).

## Context and Problem Statement

ADR-2.0.0#01 mandated `Plugin.define({ id, setup })` from a runtime `import { Plugin } from "@opencode/plugin"`. Verified on v2.0.15: the v2 server plugin loader cannot resolve ANY runtime bare package import from user plugin files — even a CJS-ready package with a complete target `node_modules` fails with `Die(ResolveMessage: Cannot find package '...')`. The same wall makes zod unloadable from `plugins/adr/adr-compaction.ts`. Separately, plugin ids share ONE runtime registry namespace with third-party npm plugins, and upstream's own examples use vendor-prefixed dotted ids (`acme.*`) — bare ids like `adr` / `usage` invite collisions OCP cannot detect or prevent.

Constraints: spawned worker processes (playwright templates) are exempt — they run as separate `node`/`bun` processes with normal resolution; `plugin-scope.json` gate names must stay decoupled (caller-supplied literals via `scopedForAgent`/`scopedForCall`, e.g. `"adr-context-tool"`); slash-command and slot names are separate namespaces with their own rules.

## Decision Outcome

Chosen option: default-export the bare `{ id, setup }` object typed via `import type { Plugin } from "@opencode/plugin"` (server) / `Plugin.Definition` from `@opencode/plugin/tui` (TUI) — `import type` is erased at transpile, and `Plugin.define` is an identity function, so the typed literal is exactly equivalent at runtime. Every plugin id carries the `opencode-prime.` prefix (`opencode-prime.adr`, `opencode-prime.usage`, …). zod is replaced by a hand-rolled candidate parser in `adr-compaction.ts` (shapes kept in sync with the JSON Schema tool inputs) and dropped from `package.json` dependencies.

**Positive**: plugins load under the real v2 loader instead of only in the source-run sandbox; one less shipped dependency; id collisions with third-party plugins become impossible in practice; the type surface (`Plugin.Plugin` / `Plugin.Definition`) is still fully checked at author time.

**Negative / Risks**: the equivalence to `Plugin.define` rests on upstream keeping it an identity function — mitigated by the loader contract being verified behavior, and `import type` gives compile-time notice if the shape ever diverges; hand-rolled validation must be kept in sync with the JSON Schema tool inputs by convention (noted at the parser site).

### Confirmation

`tsc --noEmit` clean; id-assertion unit tests updated and green (`test-lite-mode-unit`, `test-sdd-unit`, `test-tool-compress-unit`); `tests/test-all.ps1 -StructuralOnly` all green; `scripts/pack.ps1` green; `scripts/verify.ps1` fails only on the pre-existing L0 prompt-budget overflow (2717/2700, identical at HEAD — no shipped prompt file is touched by this change).

## More Information

- Bundled behavior change: `tools.tgrep` missing/omitted now defaults ON (`plugins/tgrep/tgrep-config.ts`), matching the installer's `toolEnabled` semantics — CLI-only installs never write `options.jsonc`, so a missing file is not an opt-out; unreadable/invalid config stays fail-safe disabled.
- `install/src/cli-merger.ts` extracted from `installer.ts`; package-manager fallback chain bun→pnpm→yarn→npm for plugin runtime deps; wizard keymap `enabled` predicates now evaluate at dispatch time (last-enabled wins) so background plugins no longer swallow keys.
