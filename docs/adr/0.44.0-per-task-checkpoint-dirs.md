# Iteration 0.44.0 · Per-task checkpoint directories

> Index: [`README.md`](./README.md).

## Cheatsheet

1. Resumable protocol state moves from one fixed file per protocol to a per-task directory: `.ocp/<protocol>/<slug>.md` — `/dev-deep` (since v0.43.1) and `/dev-ultra` (this ADR) (ADR-0.44.0#01)
2. Slug: derived from the requirement/objective subject, ≤ 40 chars, filesystem-safe, Unicode allowed (SDD slug convention); announced at planning (ADR-0.44.0#01)
3. `--resume[=<slug>]`: explicit slug resumes that task; bare `--resume` auto-picks a single checkpoint or lists several for the user to choose (ADR-0.44.0#01)
4. Same-slug ACTIVE checkpoint without `--resume` → guard question (resume / overwrite / abort) — never a silent clobber (ADR-0.44.0#01)
5. Legacy `.ocp/dev-ultra-state.md` gets **no v2 support at all** — neither resumed, nor migrated, nor git-ignored (v2 amendment to ADR-0.44.0#01); stale copies left in user workspaces are dead data
6. Amends ADR-0.35.0#01 (artifact table, "Logs + dev-ultra state" row): runtime target is now `.ocp/dev-ultra/<slug>.md`; the single file remains as migration source + fallback, still disposable (ADR-0.44.0#01)

### 01. One checkpoint per task, not per protocol
**Status**: ✅ accepted

**Background**: `/dev-ultra` wrote a single `.ocp/dev-ultra-state.md`. Two concurrent — or interleaved — runs in one project clobbered each other's state, and `--resume` could not tell tasks apart. `/dev-deep` shipped in v0.43.0 with the same single-file design and was fixed pre-adoption in v0.43.1 (`.ocp/dev-deep/<slug>.md`); this ADR extends the same contract to `/dev-ultra` and pins it as the convention for any future resumable protocol. ADR-0.35.0#01 pinned the single path `.ocp/dev-ultra-state.md` in the OCP path contract; that row is amended here.

**Decision**:

| # | Point | Content |
| --- | --- | --- |
| 1 | Layout | Resumable protocol state lives at `.ocp/<protocol>/<slug>.md` — one file per task; the directory is created on first write and git-ignored as a whole |
| 2 | Slug | Derived from the requirement/objective subject (≤ 40 chars, filesystem-safe, Unicode allowed — SDD slug convention); announced at planning so the user can note it for `--resume=<slug>` |
| 3 | Resume | `--resume=<slug>` resumes a specific task; bare `--resume` auto-picks the single checkpoint, or lists candidates (objective, timestamp, progress) at the existing confirmation gate; checkpoint frontmatter carries `slug` + `status` (`running \| stopped \| completed`) |
| 4 | Guard | Same-slug non-completed checkpoint without `--resume` → pre-run question (resume / overwrite / abort); completed checkpoints are overwritten with an announcement |
| 5 | Legacy | The resume fallback is **dropped on v2** (major-line cut; v1 keeps it) — the legacy single file is neither migrated nor git-ignored on v2; stale copies are dead data the user may delete |
| 6 | Gitignore contract | `ensureOcpGitignore` bootstrap grows to eight lines (adds `dev-ultra/`, drops the legacy `dev-ultra-state.md` line on v2); heal appends the directory entry to existing projects |

**Rationale**:

- **Parallel runs are legitimate** — nothing in the protocols forbids two objectives in flight; the state layout must not
- **Directory over suffixed files** — `.ocp/<protocol>/` gitignores in one line and leaves room for future per-run artifacts without further contract changes
- **Guard over lock** — prompt protocols have no file-locking primitive; an explicit pre-run question is the enforceable equivalent
- **One convention, two protocols** — dev-deep and dev-ultra now share slug/resume/guard semantics, so users learn it once

**Rejected**:

| Option | Reason rejected |
| --- | --- |
| Keep the single file, add a runtime lock | No locking primitive exists in a prompt-level protocol; a "lock" would be advisory text the model can ignore |
| Timestamp-suffixed files (`state-<ts>.md`) | Unreadable task identity; `--resume` cannot be aimed without listing anyway; slug carries meaning |
| Fold state into `.ocp/ocp.json` | State is a markdown document (phase digests, conclusions), not config; JSON-embedding fights both readers |
| Edit ADR-0.35.0 in place | Accepted records are appeal-only via a new record (ADR-0.40.3); amendment lives here |

**Impact**:

- **Skills** — `skills/dev-ultra/SKILL.md` (Arguments, Resume check, Step 4 compaction + format, Session recovery, Guardrail 8); `skills/dev-deep/SKILL.md` already compliant since v0.43.1
- **Plugin** — `plugins/shared/opencode-prime.ts`: `ensureOcpGitignore` bootstrap 7→8 lines (adds `dev-ultra/`, drops `dev-ultra-state.md` on v2) + `dev-ultra/` heal branch; the legacy migration list drops `dev-ultra-state.md` (nothing reads it on v2 — v1 retains both the migration and the fallback)
- **Tests** — `test-project-memory-unit.ts` bootstrap pin (eight lines) + heal assertion
- **Docs** — `docs/workflows/dev-loops.md` + ZH mirror (Resume line); `commands/dev-ultra.md` usage string
- **ADR** — amends ADR-0.35.0#01 artifact-table row 4; `INDEX.md` regeneration pending (generated file, tool-synced)
