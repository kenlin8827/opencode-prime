# 2.0.0 · Session language via runtime marker injection

## Context and Problem Statement

`instructions/output-protocol.md` §Session language makes `~/.config/opencode/ocp.json`'s `language` field the pre-prose default: a slash command or skill that fires before the user's first message has no instructional prose to detect, so the configured language must lock the session. A prompt rule can NAME that source, but the model still has to read the file to know the value — models do not spontaneously read config files, so the chain silently fell through to the environment default (empty `LANG` on Windows → English) and skill/command output stayed English despite the configuration.

Constraints: AGENTS.md §0 injection matrix — imperative policy the model must internalize belongs in `ctx.session.hook("context")` injection, not static prompt text; token budget — the injected fragment must stay a few lines; no agent-scope gate — every agent that produces prose needs the language.

## Decision Outcome

Chosen option: inject the resolved language as an in-context fact. `plugins/session-language.ts` reads `ocp.json` via `plugins/shared/ocp-config.ts#readOcpField` and appends a marker-guarded `[SESSION LANGUAGE: <locale>]` fragment to the system parts on every context event; the L0 rule references the marker and never the file path.

**Positive**: the configured value reaches every session regardless of what fires first; provenance lives in code (dev-only), zero file-path tokens in shipped prompts; fail-open (absent/garbage value → no injection, environment-default chain governs unchanged); variant-tolerant strip via the shared `stripBlockByPrefix` primitive.

**Negative / Risks**: ~50 tokens per request (same class as the other injectors); `ocp.json` drift (e.g. the TUI language switcher cycling locales) silently changes the session language — mitigated because the marker names its locale, making drift observable in the context itself.

### Confirmation

E2E in a fresh opencode process: config `ja` → model answers 日本語; config `zh-CN` → answers 中文 (reproduced). Unit: `bun tests/test-system-block-unit.ts` (35 passed, 8 new for `stripBlockByPrefix`); repo `tsc --noEmit` clean; `tests/test-all.ps1` FAIL set identical to HEAD baseline (pre-existing only).

## More Information

- The installer seeds `language` from environment detection on first install (`install/src/installer.ts#seedOcpLanguageFromEnv`) so the pre-prose default exists out of the box; explicit user choice (TUI wizards, `/lang`) always wins over the seed.
- `plugins/shared/ocp-config.ts` splits `realOcpConfigPath()` (ignores the `OCP_CONFIG_PATH` test pin) for installer-side migration, honoring the pin everywhere else.
