## v0.39.0 — 2026-09-15

[Compare v0.38.2...v0.39.0](https://github.com/kenlin8827/opencode-prime/compare/v0.38.2...v0.39.0)

### 🔄 Command rename: `/grill-improve-loop` → `/improve-loop`

The score-driven improvement loop has been renamed from `/grill-improve-loop` to `/improve-loop`. The new name better matches what the command actually does (iteratively drive score up → fix → re-score), and decouples it from the `grill-me` / `grill-with-docs` family — those are pre-development advisor-driven grilling sessions, while this command is a post-development polishing loop. Different intents, no shared prefix needed.

- **`commands/improve-loop.md`** — slim launcher; agent stays `build`.
- **`skills/improve-loop/SKILL.md`** — full protocol. Internal language updated for consistency: `Grill, don't console.` → `Improve, don't console.`; `subject to grill` → `subject to improve`; phase marker `[grill-improve-loop]` → `[improve-loop]`.

### ⚠️ Breaking change

Existing users who have built muscle memory for `/grill-improve-loop` must use `/improve-loop` from this version on. There is no alias — the old name is gone from the shipped surface. Users on v0.38.x can upgrade in place via the standard installer; the next run picks up the new command name automatically.

### 📝 Other references synced

`docs/`, `prompts/build.md`, `prompts/code.md`, `tests/test-all.ps1`, `DEVELOPING.md` all point at `/improve-loop` now. No other command or skill is affected; `/grill-me` and `/grill-with-docs` are unchanged.

### 🪜 Supported floor raised to 0.38.0

`install/version.json` `minVersion` moved from `0.33.0` to `0.38.0`. Manifests for `0.33.0` through `0.37.x` have been compacted into `install/versions/history.manifest.txt`; their loose copies were removed. The 0.38.x line is the new precise-upgrade baseline.

- **Users on 0.38.0 or newer**: no behavior change — the installer skips the floor warning and uses the precise per-version manifest for stale-file cleanup.
- **Users on 0.33.0 ~ 0.37.x**: the next install prints `Installed v<X> is below the supported floor v0.38.0 — upgrading on a best-effort basis.` and falls back to a live repo scan for orphan cleanup (bounded). Upgrade itself still completes normally.
- **Historical content preserved**: every file path previously listed in the removed manifests is still present in `history.manifest.txt` (deduplicated union) so uninstall semantics for any shipped version remain intact.
