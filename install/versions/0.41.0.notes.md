## v0.41.0 — 2026-09-22

[Compare v0.40.3...v0.41.0](https://github.com/kenlin8827/opencode-prime/compare/v0.40.3...v0.41.0)

### 🔁 E2E guard retired → `/e2e-adopt` docs governance (breaking for `e2eGuard` users)

The `e2e-guard` plugin is retired and replaced by **`/e2e-adopt`**, which scaffolds the E2E red-line policy into the project's **own documentation** (`docs/e2e-redline.md` + a marker-framed section in `AGENTS.md`) instead of injecting a generic protocol at runtime.

Why: the retired plugin's hard command gate was never registered (dead code — the runtime was already soft-only), and a generic injected protocol can never know a project's real test command, spec directory, or critical journeys. baijiu-shop-style docs governance puts that precision where it belongs — in project-owned documents, editable by the project. The new plugin carries no runtime hooks at all: no prompt injection, no tool gate, no switch field.

**`/e2e-adopt` behavior** (user-invoked only — the command IS the consent):

- `/e2e-adopt` — detect → write `docs/e2e-redline.md` (create-only, never overwrites) + insert the AGENTS.md red-line section (marker-framed, idempotent) → full report
- `/e2e-adopt dry` — preview, write nothing
- `/e2e-adopt status` — adoption report
- Uninstall = delete `docs/e2e-redline.md` + the `<!-- e2e-redline -->` section in AGENTS.md

The adopted policy carries the four core elements: risk-graded tiers (lightweight / targeted / full), a confirmation loop (ask before ANY E2E run; an explicit request in the current turn counts as confirmed; a refusal pauses the commit), trigger discipline (E2E only at commit/push time — code-only requests get lightweight verification), and a coverage mandate (`feat`/API changes carry proportionate E2E coverage, committed in the same batch), plus a pre-commit checklist and counter-examples.

**Stack-agnostic by design**: detection only pre-fills what is genuinely universal (conventional e2e directories, runner-config hints). The E2E command is never guessed — `{{E2E_COMMAND}}` stays a placeholder for the agent (inspect the repo) or the user to fill; the command is single-sourced in `docs/e2e-redline.md`. Malformed AGENTS.md marker framing (crossed/duplicated) is detected and refused rather than spliced.

### ⚠️ Breaking / migration

- The `e2eGuard` field in `.ocp/ocp.json` becomes **inert** (harmless leftover; may be deleted by hand). `/e2e-guard` no longer exists.
- Projects that relied on the injected protocol should run **`/e2e-adopt`** once, then let the agent fill `{{E2E_COMMAND}}` / `{{E2E_DIR}}` / `{{CRITICAL_JOURNEYS}}` in `docs/e2e-redline.md`.
- The TUI sidebar no longer shows an `e2e-guard` badge; the wizard's Guards group now covers env + ADR only.

### 🔖 Why a minor bump

Plugin retirement + new command + behavior change for existing `e2eGuard` users — a feature-level change, so the minor bump applies (`DEVELOPING.md` §Adding a new skill or command, step 6).
