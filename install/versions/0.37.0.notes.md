## v0.37.0 — 2026-09-14

[Compare v0.36.1...v0.37.0](https://github.com/kenlin8827/opencode-prime/compare/v0.36.1...v0.37.0)

### 🪝 DeepSeek-anchor → OCP path contract (ADR 0004)

- **Single-source global config** — `deepseek-anchor` no longer reads `~/.config/opencode/opencode.jsonc` or a state file; the only on-switch is now `deepSeekAnchor` in `~/.config/opencode/ocp.json`. The plugin is a USER preference (model behavior, follows the user), analogous to `i18n`, not a project-scoped switch like `auto-advisor` / `adr-guard`.
- **Default flipped to "off"** — opt-in. The anchor forces DeepSeek V4 Pro through a reasoning checklist before any tool call, paying a first-turn latency cost. Fresh installs default to off; explicit `/deepseek-anchor on` enables.
- **Single new file** — `plugins/shared/ocp-config.ts` exposes `readOcpField` / `writeOcpField` / `normalizeOnOff` to the whole OCP plugin suite (previously only `i18n` used it). The shared `normalizeOnOff` also absorbed the private copy that lived in `sidebar-status.ts`.
- **Local subagent tracking removed** — delegated entirely to `scoped()` (`plugin-scope.json` `*` deny `["lite", "utility", "subagent:*"]`). Subagent sessions are gated at `experimental.chat.system.transform`; `anchoredSessions` never holds a subagent ID, so `tool.execute.before` is automatically inert. No local `subagentSessions` set, no `session.created` event handler. Behavior contract documented inline at `plugins/deepseek-anchor/index.ts:96-112`.

### 🔧 Hardening

- **`/deepseek-anchor on|off` failure path surfaces** — `setMode()` now returns `boolean` (via `writeOcpField`); the command hook surfaces `false` to the user with `ocpConfigPath()` instead of swallowing the error.
- **Sidebar badge parity** — `resolveDeepSeekAnchor()` mirrors `getMode()` exactly (same source, same normalizer); drift surface is 2 LOC.
- **Test-all smoke ref** — `tests/test-all.ps1:292` stale reference to the deleted `deepseek-anchor-announce.ts` removed.

### 📋 Test coverage

- **`test12_StructuralInvariants`** — three Tier-1 assertions lock the round-2 pivot: project-level `deepSeekAnchor` is ignored; `setMode("on")` leaves live `<cwd>/.ocp/ocp.json` snapshot unchanged; `setMode("on")` returns `false` on permission-denied (with a chmodHonored probe so the test fails loudly on platforms that ignore chmod).

### ⚠️ Migration notes for v0.36.1 users

- Users who previously wrote `deepSeekAnchor` to `~/.config/opencode/opencode.jsonc` — that key is now silently ignored. Recovery: run `/deepseek-anchor on` once to write the value into the global `ocp.json` (or edit `~/.config/opencode/ocp.json` by hand).
- Users who never explicitly toggled — behavior change: default is now `off` (was `on` pre-v0.36.1). If you relied on the implicit-on default, run `/deepseek-anchor on` after upgrade.
- The deleted state file `~/.config/opencode/.deepseek-anchor-enabled` (pre-v0.15.0) is also no longer consulted — clean up manually if you care.
