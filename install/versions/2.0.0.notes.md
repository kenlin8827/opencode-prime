# OpenCode Prime 2.0.0

Release date: 2026-09-24 · Runtime line: **opencode 2.0.x** · Previous line: 0.x (opencode v1)

This release **resets the version line to 2.0.0**: the suite is now built for and
adapted to the OpenCode v2 runtime. Historical 0.x manifests and notes were
cleared from `install/versions/` as part of the reset; 2.0.0 is the new baseline.

## What changed

The adaptation targets the v2 runtime's native surfaces — no v1 compatibility
shim ships in the plugin tree (see ADR-2.0.0).

- **Plugins rewritten on the native v2 API** (`@opencode/plugin` ^2.0.15):
  every entry is a `Plugin.define({ id, setup })`; behavior registers through
  domain hooks (`ctx.session.hook`, `ctx.tool.hook`, `ctx.permission.hook`,
  `ctx.shell.hook`), synchronous registry transforms (`ctx.tool.transform`,
  `ctx.command.transform`, `ctx.model.transform`, `ctx.agent.transform`, …)
  and the `ctx.event.subscribe` stream. The v1 `server()`-export contract is
  gone (hard cutover).
- **V2-native root config** (`opencode.template.jsonc`): `agents` (plural),
  ordered `permissions[]` rules (`{action, resource, effect}`, last match
  wins), `providers` entries shaped `{ package, settings }`, `plugins`
  entries as string or `{ package, options }`, MCP under `mcp.servers`.
  There is no root `model`/`small_model` preset on a fresh install; the
  flash tier's model ref lives in `agents.title.model`.
- **Terminal client config**: `tui.template.jsonc` is replaced by
  `cli.template.jsonc`, merged into ONE global `~/.config/opencode/cli.json`
  (the layered v1 `tui.json(c)` is retired; a legacy v1 `tui.jsonc` plugin
  list is migrated into `cli.json` on the first v2 run). TUI plugins moved to
  `plugins/tui/` and were ported to the `@opencode/plugin/tui` slot/keymap
  API.
- **Per-agent gating**: v2 has no per-agent hook scoping, so
  `plugins/shared/agent-scope.ts` restores the plugin-scope semantics on v2
  events (event `agent` ID → system-text sentinel → `parentID` ground truth;
  fail-open). Question authorization (auto-advisor / ADR compaction
  user-channel trust) was re-implemented on `ctx.tool.hook("execute.after")`.
- **Installer un-locked from the v1 major**: the opencode install channel
  (`@script:opencode`) resolves the newest **v2** release and upgrades an
  in-profile v1 binary in place; a both-direction runtime/package compat gate
  refuses a v1 runtime with the 2.x package (and vice versa) before touching
  anything; v3+ binaries are never downgraded without consent.

## Known gaps (OCP-V2-GAP registry)

The v2 plugin surface lacks some v1 affordances; the code marks every accepted
degradation with an `OCP-V2-GAP` comment. Summary:

| Gap | Impact | Where |
|---|---|---|
| No TUI notification domain in the v2 plugin `Context` | v1 toasts degrade to a server-log announce line (`[ocp:notify]`) | `plugins/shared/notify.ts`; announce paths in auto-advisor, project-manager, adr |
| Inbox API cannot rewrite a pending item's payload | `/queued` "Edit text" removed; list / view / steer↔queue toggle / cancel remain | `plugins/tui/queue-manager.ts` |
| v2 durable model folds steps into one assistant message per turn | `/usage` "Steps" column counts assistant messages as the closest proxy | `plugins/tui/usage.ts` |
| `Tool.Result` has no `title` field | tgrep / memory-note tool result titles dropped, text preserved | `plugins/tgrep.ts`, `plugins/project-memory/project-memory-tool.ts` |
| v2 `Command` carries no per-command model/variant | command-level variant rewriting is not ported (upstream gap); model/agent variant folding works | `plugins/model-variants.ts` |
| Select dialog always shows its filter | provider wizard form sheets lost v1's `renderFilter: false` — cosmetic | `plugins/tui/provider-wizard.ts` |

**Deferred**:

1. **Variant folding semantics** — v1's dangling-variant tolerance does not
   exist in v2 (the resolver errors on a variant a model no longer declares),
   so effort refs are *folded onto proven sibling models* and the variant is
   cleared. Undeclared size-suffix families never rewrite.
2. **Provider presets shape** — `providers/*.json` presets keep the v1
   definition shape and rely on the runtime's legacy normalization; migrating
   them to a v2-native preset surface (or the `ctx.provider.transform`
   registration path) is deferred to a follow-up iteration.

## Upgrading from 0.x (v1 runtime)

OCP 2.0.0 cannot be applied over a 0.x install by `ocp update` / `ocp upgrade` —
the major-version lock (ADR-0.41.0) refuses the jump. Deliberate path:

1. `ocp init` — backs up and clears the target config.
2. Run the quick-install one-liner for your platform (README): it downloads the
   newest release, and the 2.x installer then resolves and pins the newest
   **v2** opencode runtime (an in-profile v1 binary is upgraded in place; v2
   keeps the same config locations).

API keys, custom provider/model definitions and tier selections are preserved
by the config merger; a v1 `tui.jsonc` plugin list is migrated to `cli.json`
automatically. `agents.title.model` replaces v1's root `small_model` via the
runtime's own config normalization.
