### 🛠️ `/dev-ultra` checkpoints are per-task (parallel-run safe) — ADR-0.44.0

Same defect class as `/dev-deep` v0.43.0 (fixed there in v0.43.1): the single `.ocp/dev-ultra-state.md` meant two concurrent or interleaved `/dev-ultra` runs in one project clobbered each other's state, and `--resume` could not tell objectives apart. Checkpoints now live at **`.ocp/dev-ultra/<slug>.md`** (one file per objective; slug derived from the objective, announced with the plan):

- `--resume=<slug>` resumes a specific objective; bare `--resume` auto-picks the single checkpoint or lists several at the plan-confirmation gate.
- Same-slug ACTIVE checkpoint without `--resume` → guard question (resume / overwrite / abort) — never a silent clobber.
- Checkpoint frontmatter gains `slug` + `status` (`running | stopped | completed`).
- **Legacy fallback**: an in-flight pre-0.44.0 run keeps working — if `.ocp/dev-ultra/` holds no checkpoint and the old single file exists, `--resume` reads it and subsequent checkpoints migrate into the directory (announced).

Governance: amends ADR-0.35.0#01 (path contract, "Logs + dev-ultra state" row) — see `docs/adr/0.44.0-per-task-checkpoint-dirs.md` (+ ZH mirror). `.ocp/.gitignore` contract grows to eight lines (adds `dev-ultra/`; the legacy `dev-ultra-state.md` line stays for the fallback). `INDEX.md` regeneration is tool-synced (`/adr`), pending.

### 🔖 Why a minor bump

User-facing protocol behavior change (`--resume` grammar, checkpoint layout) + `.ocp/.gitignore` contract extension + ADR-pinned path amendment — feature-level per `DEVELOPING.md` §Adding a new skill or command, step 6.
