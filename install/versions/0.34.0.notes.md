### 🧠 project-memory — full redesign (headline)

v0.33.0 shipped phase 1 as `memory.md` (single file, draft→curated manual promotion). v0.34.0 replaces that with the minimal design that holds up at scope: two self-describing files inside the project, LLM-driven capture, session summaries, and a freshness signal.

#### Two scopes, one gate

- **`public.md`** — committed to git, reviewed by your team through the normal PR flow. Same authority tier as `AGENTS.md`.
- **`private.md`** — gitignored, only the current user sees it. Auto-gitignored on first capture via `.opencode/.gitignore`.
- Both live inside `<projectDir>/.opencode/memory/` (same convention as `.opencode/handoffs/`, `.opencode/logs/`, `.opencode/recovery/`). No user-home storage, no `projectKey` hashing — the project IS the identity.
- Single marker `[PROJECT MEMORY]` with `=== Public ===` / `=== Private ===` sections; `AGENTS.md` stays authoritative on conflict.

#### Naming & API convergence

The design went through three iterations to land the right vocabulary — `capture` was wrong (the verb implied auto-grab), so it became `note` (what the user actually does). The session-summarize command went `/memory-summarize` → `/remember` → back to `/memory-summarize` — the final form reuses the `summarize` mental model users already have from Notion/Slack/Linear (zero new vocabulary to learn). File names went `memory.md` → `public.md` / `private.md` so visibility is unambiguous without docs.

**Final user-facing API:**

```text
/memory note "<lesson>"             # public (committed, PR-reviewed)
/memory note --private "<note>"     # private (gitignored, current-user only)
/memory on | off                    # injection gate
/memory status                      # counts + gate state
/memory show                        # preview what's currently injected
/memory-summarize [focus]          # LLM reviews the session, captures durable lessons
```

**`memory_note` tool** — registered as an OpenCode tool so the LLM can call it when it discovers a reusable rule during work. Defaults to `public`; pass `scope: "private"` for personal notes. Self-rated `confidence` (`high`/`medium`/`low`) is metadata only, not gated.

**`/memory-summarize` skill** — `commands/memory-summarize.md` (thin launcher, `agent: lite`) + `skills/memory-summarize/SKILL.md` (5-step protocol). Supports a positional `<focus>` arg to narrow extraction ("`/memory-summarize "API quirks" --public`" only captures API-related team lessons). When focus matches nothing, the skill explicitly reports "no matches" rather than silently broadening — a hard floor on noise.

#### Staleness signals

Per-chat staleness injection so the LLM can see how fresh memory is:

- Top-of-fragment: `(Project memory last updated: 2026-09-12 14:23. If notes are stale, suggest /memory-summarize to refresh.)`
- Per-section header: `=== Public (3 entries, last edited 2026-09-12 14:23) ===` — adds `— STALE` suffix when the source is older than 30 days, so the model can mechanically act on it instead of guessing dates.

### 🔒 plugin-scope — unified gate API

v0.33.0 scoped system-inject via `plugin-scope.json`. v0.34.0 generalizes that to also gate tools, through a single policy engine:

- **`scoped(input, system, pluginId, client?)`** — for `experimental.chat.system.transform` hooks. Detects agent via system-text probe (`lite` / `utility` markers) plus parentID ground truth for subagent sessions.
- **`scopedForTool(input, pluginId, client?)`** — new, for `tool.execute` handlers. Detects agent via `input.agent` string (OpenCode's `ToolContext` carries agent name but no system text). Falls through to parentID detection when no agent name matches.
- New `detectAgentByName(agent)` helper maps OpenCode agent names to scope identifiers (`title-generator` / `title` / `utility` → `utility`; `lite` → `lite`).
- `evaluate()` core policy logic shared between both entry points.

`plugin-scope.json` now registers two project-memory keys, independently tunable:

| Key | Scope | Default policy |
|---|---|---|
| `project-memory` | `[PROJECT MEMORY]` system-inject | Lite allow, subagent deny (narrow-context pollution), utility deny (title tasks don't need it) |
| `project-memory-note-tool` | `memory_note` tool execute | Utility deny (title generator can't discover reusable rules; a stray note pollutes the files), subagent allow (advisor subagent may legitimately learn a project quirk worth remembering) |

This split keeps the two gates independently tunable — tightening one doesn't affect the other.

### 👀 `/memory show` — user-visible memory

The biggest UX gap in v0.33.0 was that users couldn't see what the LLM was actually seeing — sidebar only showed a count. v0.34.0 closes it:

```text
$ /memory show
[project-memory] Active memory preview (what the LLM sees on each chat request):

=== Public (3 entries, last edited 2026-09-12 14:23) ===
<public.md content>

=== Private (2 entries, last edited 2026-09-08 03:45) — STALE (>30 days), consider review ===
<private.md content>

Files:
  public:  /…/.opencode/memory/public.md
  private: /…/.opencode/memory/private.md
```

Users can now confirm what the LLM sees, when each piece was last touched, and which entries are stale enough to warrant a `/memory-summarize` review.

### 🤖 Agent prompts

`prompts/lite.md`, `prompts/code.md`, `prompts/build.md` each get a `memory_note` bullet under Tool selection / Hard rules:

> proactively call the `memory_note` tool when you discover a clear, reusable rule that future sessions on this project should know. Don't wait for the user to ask — it's a good habit, not an extra step. Default `public` scope (committed, PR review); use `scope: "private"` for notes only you need.

Each bullet is concise (point to the tool description for the full scope heuristic + noise rules) — same pattern other tool bullets use.
