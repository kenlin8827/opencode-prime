### 🎯 `/dev-deep` — mine-first deep-task protocol

New standalone workflow protocol for **requirements too vague to write acceptance criteria** (code or analysis): 6-part requirement mining (literal / true goal / implicit scope / anti-goals / ambiguities / understanding gate) → gated task-tree planning (todowrite-backed; every ⚠ node traces to a mining conclusion) → node-wise execution with fixed brakes (subtree retry ≤ 2 with a method change, replan ≤ 2, probes ≤ 2) → delivery with audit trail and Recovery Card.

- Launcher: `/dev-deep <requirement> [--auto] [--retry=N] [--budget=N] [--resume]` (agent: build). Standalone protocol — **not** a `/dev` preset (mining → tree → gated loop is a different topology than the single-pass compositor).
- Checkpoint/resume: `.ocp/dev-deep-state.md` written at every node boundary; `--resume` continues from the first uncompleted node.
- Family positioning: vague → `/dev-deep`; light clarify + plan → `/dev-plan`; large multi-phase objective → `/dev-ultra`; contract-ready → `/goal`; risk-first FMEA → `/dev-prud`.
